## Agent Services Workflow — Step by Step

### 1. Request creation
- User opens add.php
- They choose:
  - `customer_type`: `External` or `Internal`
  - `service_type`: `Cash to E-Cash`, `E-Cash to Cash`, or `E-Cash to E-Cash`
- The form shows fields dynamically based on that selection:
  - `External Cash to E-Cash` → provider, amount, agent details, assign-to
  - `External E-Cash to E-Cash` → admin-only fields or customer details
  - `Internal Cash to E-Cash` → internal e-cash needed, cash needed, assignment
  - `Internal E-Cash to Cash` → internal e-cash sent, cash needed, assignment
- Cash denomination details can be captured via the denominations modal.
- The controller builds a `metadata` payload and saves the row with:
  - `status = Pending`
  - `creator_id`
  - `assigned_to`
  - `metadata` JSON
  - optional `denominations` (if cash is involved, denomination is required)

### stage 2. Confirm/Approve or reject request details
- In edit.php, the edit page is used for confirmation or completion.
- The assigned user reviews or updates:
  - denominations verification where cash is involved
  - photo upload where e-cash is coming in 
  - cash amounts
  - metadata fields
  - here is where 2nd stage is carried: upload picture proof if ecash is coming in. enter cash received denominations if cash is coming in. if its internal, display the assigned sim details of user who is in need of ecash based on selected service. for example, if selected service is mtn, display assigned sim details of mtn for the user (check how assigned sims details are captured in requests at the backoffice)
  - remarks
  - Approve sets status `Approved` and stores `approver_id`.
  - Reject sets status `Rejected`.
  - These actions are gated by:
  - `agent_services_can_approve()`
  - `agent_services_can_reject()`
- On submit with `action_type=confirm`, the controller updates:
  - `status = Confirmed`
  - `processor_id = current user`
  - `metadata` and `denominations`
- This is the explicit “confirmed by processor” stage.

### stage 3. Complete the transaction
- When status is `Confirmed` or `Processing`, the action center shows `Complete`.
- `agent_services_can_complete()` allows completion by:
  - creator
  - assigned user
  - processor
  - admin/manager
- The completion flow lives in agent-services-controller.php and calls:
  - `agent_services_apply_atomic_updates($id)`
- This helper applies the actual cash / e-cash movements using `BackOfficeCashdrawer` functions.

###. Settlement behavior by service type (cashdrawer syncing and update)
The helper routes the settlement based on `service_type`:

For internal transaction
- `Cash to E-Cash`
  - cash movement `out`
  - e-cash movement `in`

- `E-Cash to Cash`
  - e-cash movement `out`
  - cash movement `in`

- `E-Cash to E-Cash`
  - e-cash movement `out` from one channel
  - e-cash movement `in` to another channel

  For external transaction
- `Cash to E-Cash`
  - cash movement `in`
  - e-cash movement `out`

- `E-Cash to Cash`
  - e-cash movement `in`
  - cash movement `out`

- `E-Cash to E-Cash`
  - e-cash movement `in` from one channel
  - e-cash movement `out` to another channel

The helper chooses channels from:
- `provider`
- `paying_network`
- `receiving_network`
- metadata fields like `ecash_needed`, `ecash_sent`, `transfer_network`

###. Final status update
- If atomic updates succeed:
  - status set to `Completed`
  - `date_completed` is recorded
- If settlement fails:
  - status set to `Failed`
  - failure reason is written to status history

###. Action center behavior
The view.php action center now shows the next correct step:
- `Confirm` / `Approve` / `Reject` when pending. 
- `Edit & Confirm` if the assigned user is allowed to confirm first
- `Complete` when confirmed/processing

###. Metadata tracking
Important data stored in `metadata`:
- `customer_type`
- `service_type`
- `agent_name`, `agent_number`, `business_name`
- `provider`, `paying_network`, `receiving_network`, `transfer_network`
- `cash_received_amount`, `change_required`
- `change_denominations`
- `ecash_needed`, `ecash_sent`
